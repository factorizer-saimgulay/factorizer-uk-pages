This page describes the error body that every failed API request returns and lists every error code found in code. It covers the 213 code constants in src/cluster_erp/core/errors.py, the codes that modules and server files define locally, and the codes that the exception handlers in src/cluster_erp/server/error_handler.py assign. The design of the error model is explained in Errors and exceptions.

Error body¶

Every handler builds the body with _build_body. From src/cluster_erp/server/error_handler.py:33-46:

def _build_body(
    code: str,
    message: str,
    trace_id: str,
    details: dict[str, Any] | None = None,
) -> dict[str, Any]:
    body: dict[str, Any] = {
        "code": code,
        "message": message,
        "trace_id": trace_id,
    }
    if details:
        body["details"] = details
    return {"error": body}

Illustrative response built from _build_body and the RESOURCE_NOT_FOUND factory not_found (src/cluster_erp/core/errors.py:357-367):

{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "Warehouse (<warehouse_id>) not found",
    "trace_id": "<yymmdd>-<seq>",
    "details": {"resource": "Warehouse", "id": "<warehouse_id>"}
  }
}
Field Meaning
code Machine-readable code. Clients map it to a localised message (src/cluster_erp/core/errors.py:6-16).
message Developer-oriented English text (src/cluster_erp/core/errors.py:10-11).
trace_id Date prefix yymmdd and a daily sequence from the trace_sequence table; a time-based fallback when the table write fails (src/cluster_erp/server/error_handler.py:49-70).
details Present only when not empty (src/cluster_erp/server/error_handler.py:45-46).
debug_message, exception_type Added for unhandled and mapped exceptions only when debug is on (src/cluster_erp/server/error_handler.py:306-308, src/cluster_erp/server/error_handler.py:346-347).

Note

A request whose Content-Length exceeds max_request_body_bytes is refused with 413 and code REQUEST_TOO_LARGE before the body is read. That body carries code and message but no trace_id (src/cluster_erp/server/app.py:1396-1411).

Codes defined in the core error module¶

One table per comment section of src/cluster_erp/core/errors.py. Status, raise-site count, and first site come from a syntax-tree scan of src/cluster_erp/ for AppError(...), the factories in core/errors.py, and HTTPException(...). The message column quotes the English message at the first site; it is the cause as the code states it. A code with no raise site is defined but not raised by any scanned call. Codes the exception handlers assign show the handler instead.

Codes of the business sections of the same file (CRM to procurement) are listed on Business error codes.
