System endpoints API

Health, readiness, security.txt, metadata, module list, display switches, signup, and operator console endpoints: 28 routes outside the modules.

Contents

This page lists the 28 endpoints that are not part of a business module: the 7 routes that create_app declares in src/cluster_erp/server/app.py, the 6 signup routes, and the 15 operator console routes. Signup and operator console routes exist only when multi_tenant is on (src/cluster_erp/server/app.py:1440-1457). They are described here at mechanism level only.

Group facts¶

Item Value Source
Endpoints 28: 7 in app.py, 6 in signup.py, 15 in vendor.py @app.get and @router.* decorators
Mount condition signup.py and vendor.py routers when settings.multi_tenant is true; otherwise only the closed-signup probe src/cluster_erp/server/app.py:1440-1457
Operator authentication Separate operator token in the Authorization header, read by require_operator; the router also depends on _client_address_allowed src/cluster_erp/server/routes/vendor.py:68-70, src/cluster_erp/server/routes/vendor.py:84-95
Cross-origin access Only /api/v1/vendor/fleet, only for the configured console origins src/cluster_erp/server/app.py:1363-1389
Error format See Errors src/cluster_erp/server/error_handler.py:33-46

Application routes¶

create_app declares these routes directly with @app.get. Health and readiness answer without a credential; the module list, metadata, and switches require a signed-in user. The readiness contract is described in Security.txt and readiness.

GET /.well-known/security.txt security_txt none text/plain or 404 Body from security_txt_body; 404 when it returns None. Excluded from the schema. src/cluster_erp/server/app.py:1460
GET /health health none {"status": "healthy", "version": ...} Liveness: no external check. src/cluster_erp/server/app.py:1469
GET /ready ready none 200 or 503 with status and checks Probes the database and, when present, the control plane under readiness_timeout_seconds. src/cluster_erp/server/app.py:1475

Static web app mounts¶

When the webapp folder exists, create_app mounts it twice: /app/v serves files under a stamp segment, and /app serves the same files with Cache-Control: no-cache and index.html for the root (src/cluster_erp/server/app.py:1634-1645). The web app is described in Web app overview.

Signup endpoints¶

The public self-service signup flow: an availability probe, the signup request, the verification of the mailed link, a resend, a cancel, and a status poll. Requests that create work are rate-limited per client, and the poll and resend calls carry the signup token in the body, never in the URL (src/cluster_erp/server/routes/signup.py:102-112). The flow is explained in Signup.

Operator console endpoints¶

The operator console API under /api/v1/vendor: operator sign-in, the operator's own record, console metadata, the overview, tenants, the minimised fleet view, signups, the operator action log, membership changes, seed refresh, and tenant backups. Every route except sign-in requires an operator token; operator accounts and tokens are separate from tenant users. The console is explained in Operator console.
