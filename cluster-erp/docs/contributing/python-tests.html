Python tests

The pytest suite of Cluster ERP in tests/, its configuration, how to run it, and how live tests are waived with CLUSTER_SKIP_LIVE_TESTS.

Contents

  • Related pages

The Python tests of Cluster ERP live in tests/ and run with pytest. This page lists the configuration, the command CI uses, the files grouped by area, and the rules for tests that need a live server or database. Browser tests are a separate suite; see e2e battery.

Scope and source¶

  • Defined in: tests/test_*.py and [tool.pytest.ini_options] in pyproject.toml.
  • Run by: the CI job test (.github/workflows/ci.yml:124).
  • Count: 106 test files, counted with ls tests/test_*.py. The folder has no conftest.py, and the repository root has none either (searched with ls).

Configuration¶

Name Value Meaning Source
asyncio_mode auto async def tests run without a marker pyproject.toml:152
testpaths tests pytest collects only tests/ pyproject.toml:153
pytest >=8.0.0 Version floor in the dev extra pyproject.toml:81
pytest-asyncio >=0.24.0 Version floor in the dev extra pyproject.toml:82

Running the tests¶

CI runs the suite after it has applied all migrations to an empty PostgreSQL 16 database (.github/workflows/ci.yml:113, .github/workflows/ci.yml:124):

python -m pytest -q --no-header -p no:cacheprovider

The same job sets CLUSTER_SKIP_LIVE_TESTS to 1 (.github/workflows/ci.yml:99). The workflow comment states why: the live guards need a booted server, and CI waives them so that the waiver is visible (.github/workflows/ci.yml:17-20).

Live tests¶

A live test needs a running server or a reachable test database. Eight files read CLUSTER_SKIP_LIVE_TESTS (counted with grep -l). They use two patterns.

Pattern Behaviour Files Source
Skip the whole module when waived A module-level skipif skips every test when the variable is 1 test_cal03_owner_calendars_live.py, test_calendar_owner_inherits_group_live.py, test_change_history_tables_live.py, test_deactivation_sweep_live.py, test_demo_data_live.py, test_login_budget_live.py tests/test_demo_data_live.py:24-27, tests/test_cal03_owner_calendars_live.py:22-24
Fail unless waived Without a server the test fails; only the variable turns the failure into a skip test_readiness_contract.py, test_search_contract.py tests/test_readiness_contract.py:37-44, tests/test_search_contract.py:162-171

The second pattern exists because "a silently skipped guard is indistinguishable from a passing one" (tests/test_readiness_contract.py:12-14). The live HTTP tests read the server address from CLUSTER_E2E_BASE, the same variable the browser battery uses (tests/test_readiness_contract.py:27).

Other tests depend on their environment without that variable:

Condition Behaviour Source
No reachable database The partial-index and foreign-key index checks skip tests/test_live_row_uniqueness.py:88-89, tests/test_fk_indexes.py:97-98
No bash on the machine The node script tests skip tests/test_bootstrap_node_script.py:35, tests/test_pg_tune_script.py:32
No bash or git The install script test skips tests/test_install_role_gate.py:41-44

The architecture guards are explained on architecture boundaries. The static quality test runs Ruff and mypy; see lint and type check. tests/test_e2e_db_isolation.py checks the browser suites as text; see e2e battery.

Constraints and validation¶

  • Tests that start subprocesses or reach a database name their own database; the battery isolation guard applies to the browser suites only (tests/test_e2e_db_isolation.py:1-19).
  • Not determined from code: a coverage measurement. No coverage tool is declared in pyproject.toml and none runs in .github/workflows/ci.yml.
