Documents module (documents)

Module page for documents, with typed documents linked to any record, numbered versions, activation through an approval chain, and document types.

The documents module in src/cluster_erp/modules/documents/ keeps controlled documents. A document has a type, may be linked to any record by entity type and id, and carries numbered versions. One version at a time is active; a new version becomes active either at once or through an approval chain. The module also provides the "documents attached to this record" capability that the web app finds by metadata.

What the module does¶

  • Keeps documents with a business code, a type, a title, translations, a description, and an optional link to any record through entity_type and entity_id (src/cluster_erp/modules/documents/documents/models.py:26-49).
  • Keeps numbered versions per document; each version points to a file in the core attachments store (src/cluster_erp/modules/documents/documents/models.py:52-87). Storage is described on attachments, notes, and storage.
  • Activates a version directly or after an approval chain decides, and marks the previous active version as superseded (src/cluster_erp/modules/documents/documents/services.py:255-337).
  • Keeps document types with allowed file extensions and seeds a default set (src/cluster_erp/modules/documents/settings/models.py:11-28, src/cluster_erp/modules/documents/module.py:37-46).
  • Answers other modules: the documents of a record, and the file behind a version (src/cluster_erp/modules/documents/module.py:98-149).

Screens and metadata¶

get_metadata declares a sidebar group Documents (Turkish Belgeler) with a list section Documents and a settings section with the tab document_type (src/cluster_erp/modules/documents/module.py:232-265). The module publishes provides={"record_documents": {...}}, so the web client finds the record documents feature by capability, not by module name (src/cluster_erp/modules/documents/module.py:228-230). The record documents panel and the viewer are described on records, documents, viewer, and share.

Status and actions¶

A version is draft, active, superseded, or withdrawn (src/cluster_erp/modules/documents/documents/services.py:200-337). The diagram shows the version and approval chain.

In prose:

  1. A version starts as a draft. Only a draft can be edited or deleted (src/cluster_erp/modules/documents/documents/services.py:223-253).
  2. Submit for Approval asks GetApprovalChainForAction for the resource document_version and the action activate. Without a chain, it activates the version at once. With a chain, it calls SubmitForApproval and the version stays a draft (src/cluster_erp/modules/documents/documents/routes.py:302-351).
  3. When the auth module publishes ApprovalCompleted for a document_version with final_status approved, the handler reads the decider through GetApprovalRequestById and activates the version. Any other final status leaves it as a draft (src/cluster_erp/modules/documents/module.py:151-204).
  4. Activate needs a draft with an attachment. It marks the current active version superseded, sets the new one active with the approver and time, and emits DocumentVersionSuperseded and DocumentVersionActivated (src/cluster_erp/modules/documents/documents/services.py:255-295, src/cluster_erp/modules/documents/documents/services.py:316-337).
  5. Withdraw moves an active version to withdrawn (src/cluster_erp/modules/documents/documents/services.py:297-314).

Business rules¶

  • A version without an attachment cannot be activated (src/cluster_erp/modules/documents/documents/services.py:269-274).
  • At most one version per document is active; activation supersedes the previous one (src/cluster_erp/modules/documents/documents/services.py:316-337).
  • Tenant field values in extra are validated on create (src/cluster_erp/modules/documents/documents/services.py:110-115). See tenant fields.
  • GET /versions/{id}/file streams the file of the version from storage and answers not found when the file is missing (src/cluster_erp/modules/documents/documents/routes.py:240-268).
  • Deleting a document or a draft version sets deleted_at; bulk delete uses the core soft-delete helper (src/cluster_erp/modules/documents/documents/services.py:150-162, src/cluster_erp/modules/documents/documents/services.py:241-253).

Privacy, retention, and history¶

privacy_handlers.py lists the documents filed against a person (entity type party). Anonymisation is an operator decision (include_documents); when included, the documents are retired, their title and description replaced, and the version files reported for removal (src/cluster_erp/modules/documents/privacy_handlers.py:1-9). See privacy and data-subject requests. The module has no retention_handlers.py. Changes are captured by change history.

Analytics facts¶

This module has no analytics_facts.py.

Settings and reference data¶

Document types are reference data. On start the module seeds the default set through DocumentTypeService.seed_defaults, and Seed Defaults runs it on demand (src/cluster_erp/modules/documents/module.py:37-46, src/cluster_erp/modules/documents/settings/routes.py:52-58). seed_data.py holds 15 default types, for example form, instruction, procedure, and technical_drawing, each with an English name and a Turkish translation (src/cluster_erp/modules/documents/settings/seed_data.py:1-113).

Discrepancies¶

Note

When a version is activated after an approval, the handler builds the version service with a new, empty EventBus() instead of the application bus, so DocumentVersionActivated and DocumentVersionSuperseded from that path reach no subscriber (src/cluster_erp/modules/documents/module.py:190-195).
