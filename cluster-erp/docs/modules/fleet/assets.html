Fleet assets

Reference for the assets sub-module of fleet, with asset and asset class fields, lifecycle actions, runtime fields, and the routes.

Contents

  • Scope and source
  • Asset fields
  • Asset class fields
  • Statuses and actions
  • Routes
  • Constraints and validation
  • Terms introduced
  • Related pages

This page describes the assets sub-module in src/cluster_erp/modules/fleet/assets/. A fleet asset (FleetAsset) is one vehicle, trailer, or machine. An asset class (FleetAssetClass) groups assets and decides whether they are powered and which meters they get at birth. The module overview is on fleet module.

Scope and source¶

  • Defined in: src/cluster_erp/modules/fleet/models.py (FleetAssetClass, FleetAsset), assets/services.py (FleetClassService, FleetAssetService), assets/routes.py, assets/schemas.py, and assets/metadata.py.
  • Count: 2 tables, 10 routes (@...router. decorators in assets/routes.py), 6 ActionMeta entries in assets/metadata.py.

Statuses and actions¶

An asset is draft, active, in_maintenance, inactive, or disposed (src/cluster_erp/modules/fleet/models.py:46-52). The service holds the allowed transitions in _TRANSITIONS and refuses others with FLEET_INVALID_STATUS (src/cluster_erp/modules/fleet/assets/services.py:41-48, src/cluster_erp/modules/fleet/assets/services.py:277-305).

Action Label Condition in metadata Service rule Source
activate Activate status is draft draft or inactive to active src/cluster_erp/modules/fleet/assets/metadata.py:90-96
reactivate_service Return to Fleet status is inactive calls activate src/cluster_erp/modules/fleet/assets/metadata.py:97-103
send_to_maintenance Send to Maintenance status is active active to in_maintenance; opens a released work order src/cluster_erp/modules/fleet/assets/metadata.py:104-136, src/cluster_erp/modules/fleet/assets/services.py:300-338
return_to_service Return to Service status is in_maintenance in_maintenance to active src/cluster_erp/modules/fleet/assets/metadata.py:137-143
deactivate_asset Take Out of Service status is active active or in_maintenance to inactive src/cluster_erp/modules/fleet/assets/metadata.py:144-150
dispose Dispose status is inactive active, inactive, or in_maintenance to disposed; sets disposal_date src/cluster_erp/modules/fleet/assets/metadata.py:151-157, src/cluster_erp/modules/fleet/assets/services.py:296-297

Send to Maintenance asks for the work to be done, the mechanic or service party, a planned date, and notes (src/cluster_erp/modules/fleet/assets/metadata.py:110-135). The service creates the work order and releases it at once (src/cluster_erp/modules/fleet/assets/services.py:307-338).

In prose: an asset starts as a draft and becomes active through Activate. From active it can go to maintenance, out of service, or disposal. A work order completion returns an asset in maintenance to active when no other order is open (src/cluster_erp/modules/fleet/workorders/services.py:246-265). Disposal is final; no transition leaves disposed (src/cluster_erp/modules/fleet/assets/services.py:41-48).

Constraints and validation¶

  • Creating an asset checks that the class exists and that plate and vin are free among live rows (src/cluster_erp/modules/fleet/assets/services.py:199-233).
  • Tenant field values in extra are validated against their definitions, with the asset row as context for class-scoped fields (src/cluster_erp/modules/fleet/assets/services.py:233-235). See tenant fields.
  • A new asset gets the meters its class declares and the reminders of class-scoped maintenance plans at once (src/cluster_erp/modules/fleet/assets/services.py:238-249).
  • A class code is unique among live classes; a duplicate is refused with a conflict (src/cluster_erp/modules/fleet/assets/services.py:68-76).
  • DELETE sets deleted_at on the asset and on its live reminders. The code comment separates this record-level soft delete from the operational status inactive (src/cluster_erp/modules/fleet/assets/services.py:340-363).
