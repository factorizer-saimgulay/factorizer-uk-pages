Communication channels reference

Reference for parties/communication_channels, the channel types and the e-mail, phone, and other contact channels of a party.

Contents

  • Scope and source
  • Channel type fields
  • Channel fields
  • Routes

  • Discrepancies

  • Related pages

This page lists the fields, routes, and rules of the communication_channels sub-module in src/cluster_erp/modules/parties/communication_channels/. A channel is one way to reach a party, such as an e-mail address or a phone number, typed by a channel type. Channel types are reference data that this sub-module seeds and serves under the parties settings path.

Scope and source¶

  • Defined in: src/cluster_erp/modules/parties/communication_channels/models.py (ChannelType, CommunicationChannel), schemas.py, services.py (ChannelTypeService, CommunicationChannelService), routes.py, seed_data.py (CHANNEL_TYPE_DEFAULTS); metadata CHANNEL_META in src/cluster_erp/modules/parties/parties/metadata.py:1438 and CHANNEL_TYPE_META in src/cluster_erp/modules/parties/settings/metadata.py:370.
  • Count: 2 tables; 13 routes (@router. decorators in routes.py); 15 seeded channel types (entries with a code key in seed_data.py).

Constraints and validation¶

  • Setting is_primary on a channel clears the flag on every other live channel of the party, whatever its type (src/cluster_erp/modules/parties/communication_channels/services.py:137-138, src/cluster_erp/modules/parties/communication_channels/services.py:162-163, src/cluster_erp/modules/parties/communication_channels/services.py:226-234).
  • Seeding matches existing types by name, fills a missing code and missing translations on them, and creates the rest; it runs at every start (src/cluster_erp/modules/parties/communication_channels/services.py:73-100, src/cluster_erp/modules/parties/module.py:63-74).
  • A grep for validation_pattern in src/ and webapp/ finds it only in the model, the schemas, the metadata, and the seed data. No code at this commit checks a channel value against the pattern.
  • Other modules resolve a party's e-mail addresses through ResolveEntityEmails, which reads live, active channels of the type with code email (src/cluster_erp/modules/parties/module.py:489-536), and its contact values through GetPartyContactValues (src/cluster_erp/modules/parties/privacy_handlers.py:35-66).

Discrepancies¶

Warning

Discrepancy. The project's written engineering rules place ChannelType in parties/settings/. The model and its routes are in src/cluster_erp/modules/parties/communication_channels/ (src/cluster_erp/modules/parties/communication_channels/models.py:15, src/cluster_erp/modules/parties/communication_channels/routes.py:35-105); only its metadata CHANNEL_TYPE_META is in src/cluster_erp/modules/parties/settings/metadata.py:370. This page documents the code.
