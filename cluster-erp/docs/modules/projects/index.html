Projects module (projects)

Module page for projects, with projects opened from sales orders, items, fixtures, schedules and activities, kick-offs, meetings, actions, and the board read model.

The projects module in src/cluster_erp/modules/projects/ manages customer projects. A project (Project) is opened when a sales order's PO is received and follows a fixed lifecycle. It carries items to produce, fixtures to make, a versioned schedule with activities, a kick-off meeting, weekly meetings, and actions. A read-only board and calendar show all projects with their production reality. This page is the overview; the sub-topics have their own pages.

What the module does¶

  • Opens one project per sales order when the order's PO is received (src/cluster_erp/modules/projects/module.py:95-130).
  • Moves a project along a fixed lifecycle from planning to closed (src/cluster_erp/modules/projects/projects/services.py:32-43).
  • Keeps project items with a product breakdown and creates production orders for them (src/cluster_erp/modules/projects/items/models.py:17-80, src/cluster_erp/modules/projects/items/routes.py:88-138).
  • Keeps fixture requirements, schedules with activities and relations, kick-offs, weekly meetings, and actions (src/cluster_erp/modules/projects/module.py:66-75).
  • Reads production roll-up and hour-based earned value from the production module (src/cluster_erp/modules/projects/projects/routes.py:102-268).
  • Serves the board and calendar read model (src/cluster_erp/modules/projects/board.py:1-11).

Data model¶

Fields are listed on projects and items, actions, activities, and meetings, and schedules. Project items carry product_id, product_model_id, and product_version_id (src/cluster_erp/modules/projects/items/models.py:42-53). A project's stock_mode is common or project_striped, which decides whether its stock is kept in a project stripe of the inventory module (src/cluster_erp/modules/projects/projects/schemas.py:13). Fixture cost estimates are Numeric (src/cluster_erp/modules/projects/fixtures/models.py:47).

Screens and metadata¶

get_metadata declares a sidebar group Projects (Turkish Projeler) with the list Projects and the custom sections Board and Calendar (src/cluster_erp/modules/projects/module.py:288-320). It also declares two home widgets, Project Board and Project Calendar (src/cluster_erp/modules/projects/module.py:266-283). The board is explained on project board; home widgets on home widgets.

Status and actions¶

Status changes go through the action Change Status (transition) on projects, fixtures, and actions; schedules have Publish and Share with Customer; kick-offs have Mark as Held and Update Checklist; items have Create Production Order (src/cluster_erp/modules/projects/projects/metadata.py:55-64, src/cluster_erp/modules/projects/schedules/metadata.py:82-101, src/cluster_erp/modules/projects/kickoffs/metadata.py:43-62, src/cluster_erp/modules/projects/items/metadata.py:115-127). Status machines are on the sub-topic pages.

Business rules¶

Each sub-topic page lists its rules. Business keys come from the yearly sequences project, project_item, and fixture_requirement (src/cluster_erp/modules/projects/projects/services.py:124, src/cluster_erp/modules/projects/items/services.py:59, src/cluster_erp/modules/projects/fixtures/services.py:60).

Privacy, retention, and history¶

The module has no privacy_handlers.py. Deletes set deleted_at, including kick-offs and meetings (src/cluster_erp/modules/projects/kickoffs/services.py:122-125, src/cluster_erp/modules/projects/meetings/services.py:79-82). Changes are captured by change history.

Analytics facts¶

This module has no analytics_facts.py.

Settings and reference data¶

The module has no settings section. The board's default horizon is 7 days back and 56 days ahead, as module constants (src/cluster_erp/modules/projects/board.py:43-45).
