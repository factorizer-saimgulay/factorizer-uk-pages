Metadata model

The 45 Pydantic classes in core/metadata.py that describe modules, entities, forms, lists, detail views, actions, and the sidebar as the server-side contract for both clients.

Every module describes its screens with metadata: Pydantic objects defined in src/cluster_erp/core/metadata.py. This page lists those classes and their main fields as the server-side contract. How the web app renders them is documented on metadata rendering; the desktop client is documented in the desktop section.

Scope and source¶

  • Defined in: src/cluster_erp/core/metadata.py
  • Count: 45 classes (counted with grep -c "^class "), plus the alias LabelDict = dict[str, str] (src/cluster_erp/core/metadata.py:7). 186 calls of EntityMeta( exist under src/cluster_erp (counted with grep -rn "EntityMeta(").

LabelDict maps a language code to a text, for example {"en": "...", "tr": "..."}. Every label, placeholder, help text, and description in the metadata uses it.

How metadata is served¶

A module returns its ModuleMeta from get_metadata() (src/cluster_erp/core/module_base.py:73-74). GET /api/v1/_meta serialises every loaded module's metadata with model_dump(exclude_none=True) after the tenant-field entities are added, into one JSON document {"version": "1.0", "modules": {...}}. The document is built once per process and served with an ETag and a gzip form, and only to a signed-in caller (src/cluster_erp/server/app.py:1518-1556). A field whose value is None is therefore absent from the document.

Constraints and validation¶

  • Metadata objects are Pydantic models; a wrong literal value or a missing required field fails when the module builds its metadata.
  • At start-up the server fails if a sub_entity_table tab points at an entity without columns (src/cluster_erp/server/app.py:547-589).
  • The project's written engineering rules make the web app fully metadata-driven: screen, form, list, and action behaviour comes from metadata. tests/test_metadata_driven_rules.py and tests/test_architecture_boundaries.py:75 guard parts of this rule; see architecture boundaries.
