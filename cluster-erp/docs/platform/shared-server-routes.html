Shared server routes

The routes in src/cluster_erp/server/routes that belong to no module, the routes defined inline in server/app.py, when each is mounted, and the core service behind each.

Contents

  • Scope and source
  • Route files
  • Notes on individual files
  • Inline routes in create_app
  • Constraints and validation
  • Terms introduced
  • Related pages

Most HTTP routes of Cluster ERP belong to a module and live under /api/v1/<module>. A smaller set lives in the server itself: ten route files in src/cluster_erp/server/routes/ and seven routes defined inline in create_app. This page lists them, says when each is mounted, and names the core code behind each. Request and response schemas of every route are documented in server routes and system endpoints.

Scope and source¶

  • Defined in: src/cluster_erp/server/routes/*.py, src/cluster_erp/server/app.py
  • Count: 10 route files with 68 route decorators (counted with grep -c -E '@(router|overlay_router)\.(get|post|put|patch|delete)\(' per file), and 7 inline routes in create_app (counted from the @app.get decorators, src/cluster_erp/server/app.py:1450-1571)

The pages that explain each group:

  • Notes and attachments: attachments, notes, and storage.
  • Guided party creation and role facets: party unification.
  • Tenant fields: tenant fields.
  • Email: PDF and system mail.
  • Chat: intent assistant.
  • Signup: signup.
  • Vendor console: operator console.
  • Currencies: reference data and core i18n.

Notes on individual files¶

  • POST /api/v1/parties/composite creates a party and the role facets chosen in one form in a single transaction. It requires party.create (src/cluster_erp/server/routes/party_composite.py:1-9, src/cluster_erp/server/routes/party_composite.py:54-60).
  • party_roles.py adds POST /api/v1/parties/{party_id}/roles/customer, /supplier, and /employee, requiring customer.create, supplier.create, and employee.create. Removing a role is the facet's own deactivation, not a route here (src/cluster_erp/server/routes/party_roles.py:1-14, src/cluster_erp/server/routes/party_roles.py:58-106).
  • POST /api/v1/chat/message requires dashboard.read. The intent engine is loaded once per process on first use (src/cluster_erp/server/routes/chat.py:24-34, src/cluster_erp/server/routes/chat.py:1191-1197).
  • The vendor router accepts only operator tokens, not tenant tokens, and serves its screens as metadata from GET /api/v1/vendor/_meta (src/cluster_erp/server/routes/vendor.py:1-16, src/cluster_erp/server/routes/vendor.py:149).

Inline routes in create_app¶

Method and path Access Purpose Source
GET /api/v1/signup/ public, single-tenant mode only Answers {"signup": "closed"} so the login screen shows no signup door src/cluster_erp/server/app.py:1451-1457
GET /.well-known/security.txt public Security contact document; 404 when security_contact is empty src/cluster_erp/server/app.py:1459-1466
GET /health public Liveness: {"status": "healthy", "version":...} with no external check src/cluster_erp/server/app.py:1468-1473
GET /ready public Readiness: asks each database one trivial question within readiness_timeout_seconds; 200 or 503, naming each check src/cluster_erp/server/app.py:1475-1504
GET /api/v1/modules signed-in Name, version, and description of every loaded module src/cluster_erp/server/app.py:1507-1516
GET /api/v1/_meta signed-in The metadata document of all modules src/cluster_erp/server/app.py:1518-1556
GET /api/v1/_switches signed-in The tenant's display switches, merged from DescribeDisplaySwitches answers src/cluster_erp/server/app.py:1558-1572

include_in_schema=False hides the signup and security.txt routes from the OpenAPI schema (src/cluster_erp/server/app.py:1455, src/cluster_erp/server/app.py:1459). The API documentation pages exist only in debug mode (src/cluster_erp/server/app.py:1300-1301). Readiness and security.txt are documented in security.txt and readiness.

Constraints and validation¶

  • Server routes import module code; module code may not import other modules (tests/test_architecture_boundaries.py:46-57). The boundary test checks only files under src/cluster_erp/modules.

Warning

Discrepancy. The project's written engineering rules say that all communication between modules goes through the EventBus. party_composite.py and party_roles.py import and call the services of several modules directly (src/cluster_erp/server/routes/party_composite.py:24, src/cluster_erp/server/routes/party_composite.py:61-73, src/cluster_erp/server/routes/party_roles.py:50, src/cluster_erp/server/routes/party_roles.py:66-67, src/cluster_erp/server/routes/party_roles.py:88-89, src/cluster_erp/server/routes/party_roles.py:110-112). This page documents the code.

Warning: Discrepancy. The project's written engineering rules forbid hard-coded user-visible text. chat.py builds some reply texts in code in Turkish and English, for example src/cluster_erp/server/routes/chat.py:1229. This page documents the code.
